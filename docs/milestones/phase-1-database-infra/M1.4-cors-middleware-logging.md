# M1.4 — CORS, Middleware, and Structured Logging

## One-line summary
Made it possible for the frontend (running on a different port) to actually call the backend, and made every request leave a log line.

## The problem
Two things a browser-facing API needs from day one:
1. Browsers block cross-origin requests by default (**CORS**) — without explicit backend configuration, the frontend dev server (`localhost:5173`) simply cannot call the API (`localhost:8000`) at all; the browser rejects the response before JavaScript ever sees it.
2. With zero logging, diagnosing "why did this request fail" in anything beyond local dev is guesswork.

## What we built
- `CORSMiddleware` registered on the FastAPI app
- `backend/app/core/logging.py` — configures Python's root logger
- A custom `@app.middleware("http")` function in `main.py` that logs method/path/status/latency for every request

## How it works — CORS
```python
ALLOWED_ORIGINS = ["http://localhost:5173"]

app.add_middleware(
    CORSMiddleware,
    allow_origins=ALLOWED_ORIGINS,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```
This tells the browser, via response headers, "requests from `http://localhost:5173` are allowed to read this response." Without it, the browser's **same-origin policy** blocks the frontend's `fetch()` calls even though the backend technically responded successfully — the block happens in the browser, not the server. `ALLOWED_ORIGINS` is a hardcoded single-item list right now, with a comment flagging that it needs to grow once a real deployed frontend origin exists (Phase 9, deployment, is still pending).

## How it works — request logging
```python
@app.middleware("http")
async def log_requests(request: Request, call_next):
    start = time.perf_counter()
    try:
        response = await call_next(request)
    except Exception:
        # log before re-raising — see below
        raise
    duration_ms = (time.perf_counter() - start) * 1000
    logger.info("%s %s %s %.2fms", request.method, request.url.path,
                response.status_code, duration_ms)
    return response
```
**Middleware** in the ASGI sense wraps every request: it runs code before calling `call_next(request)` (which runs the actual route and every middleware "below" this one), then runs more code after that call returns. This is how a single function can measure "time before the route ran" vs. "time after."

The `except Exception: ... raise` block has a subtle but important reason documented right in the code: FastAPI's global exception handlers (M1.5) that convert an unhandled exception into a clean 500 JSON response run in Starlette's *outermost* middleware layer — above this logging middleware. That means if this middleware didn't catch and re-raise, a genuine server error would propagate straight past the logging line without ever being logged — the single most important case (something actually broke) would be invisible in the logs. Catching, logging with status `500`, then `raise`-ing again preserves both: the error is logged *and* still handled correctly by the exception handler above.

## Why structured, leveled logging (not `print()`)
- **Consistent format**: every log line has a timestamp, level, and logger name (`%(asctime)s %(levelname)s %(name)s %(message)s`), so log aggregation tools (or just `grep`) can filter reliably.
- **Distinguishable loggers**: `app.request` vs. `app.errors` (used in M1.5) means log volume/severity can be tuned per subsystem later without touching call sites.
- **`print()` bypasses all of that** — no timestamps, no levels, no easy way to redirect/filter — fine for a one-off script, not for a service meant to run unattended.

## Terms worth knowing
- **CORS (Cross-Origin Resource Sharing)**: the browser mechanism that blocks a page loaded from one origin (scheme+host+port) from reading responses from a different origin, unless the server explicitly opts in via response headers.
- **Same-origin policy**: the browser security default CORS headers override — without them, `localhost:5173` and `localhost:8000` are different origins and cross-origin reads are blocked.
- **Middleware**: code that runs on every request/response passing through a web framework, positioned "around" the actual route handler.

## If asked in an interview
> "CORS is configured explicitly for the frontend's dev origin — without it the browser blocks the frontend's requests entirely regardless of what the backend returns. I also added request-logging middleware with one subtlety: it has to catch and re-raise exceptions itself, because FastAPI's global error handler sits in an outer middleware layer that runs *after* this one — without the catch, a real server error would skip the logging line entirely, which is exactly the case you most need logged."
