# M0.3 — Frontend Project Init

## One-line summary
A runnable, empty React app — scaffolded with Vite — that every page since has been built inside.

## The problem
Same idea as M0.2 but for the browser side: before building login pages, course pages, or chat UI, there needs to be a React app that actually loads in a browser and hot-reloads while you develop.

## What we built
- `frontend/` scaffolded via Vite: `package.json`, `vite.config.ts`, `src/main.tsx` (entry point), `src/App.tsx` (root component), `index.html`
- `frontend/.env.example` — documents required frontend env vars (see M0.5)

## How it works
`index.html` has one empty `<div id="root">`. `src/main.tsx` is the actual JavaScript entry point — it finds that div and tells React to render the `<App />` component tree into it. This is a **single-page application (SPA)**: the browser loads one HTML page once, and everything after that (switching between login/courses/chat) is JavaScript swapping components in and out — no full page reloads (see M2.9/App.tsx's `react-router-dom` routes for how navigation works without a page refresh).

**Vite** is the build tool. In dev (`npm run dev`), it serves files with near-instant hot-module-reload — editing a component updates the browser in milliseconds without losing app state. For production (`npm run build`), it bundles everything into optimized static files (this is what later milestones like M3.9 had to be careful about — see the bundle-size notes in that doc).

## Why Vite + React + TypeScript
- **Vite over Create React App**: CRA is effectively unmaintained; Vite's dev server is dramatically faster because it serves ES modules directly instead of bundling the whole app on every change.
- **TypeScript over plain JavaScript**: catches an entire class of bugs at compile time — e.g. calling `getCourse(courseId)` with a `number` when it expects a `string` fails immediately in the editor, not at runtime in production. Every API response shape in this project (`CourseSummary`, `LessonDetail`, `MessageRead`, ...) is a TypeScript interface (see `frontend/src/api/*.ts`), so a backend field rename becomes a compile error on the frontend instead of a silent `undefined` in the UI.
- **React over Vue/Svelte**: the most widely used option, meaning the biggest ecosystem of libraries (`react-markdown`, `react-router-dom`, `@uiw/react-codemirror` — all used in this project) and the most transferable skill for a portfolio project.

## Terms worth knowing
- **SPA (Single-Page Application)**: a web app that loads one HTML shell once and handles all subsequent navigation client-side with JavaScript, rather than requesting a new HTML page from the server for every link click.
- **Hot Module Reload (HMR)**: the dev server pushes just the changed code to the running browser page instead of doing a full reload, preserving in-memory state (e.g. text you'd typed in a form).
- **Bundler**: a tool (Vite, Webpack, esbuild) that takes many source files and their imports and produces the minimal set of optimized JS/CSS files a browser actually downloads.

## If asked in an interview
> "The frontend is React + TypeScript, scaffolded with Vite. TypeScript matters a lot in a project with this many API calls — every backend response shape is a typed interface, so if the backend schema changes, the frontend fails to *compile* instead of silently breaking at runtime."
