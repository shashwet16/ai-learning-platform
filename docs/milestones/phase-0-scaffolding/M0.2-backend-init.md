# M0.2 — Backend Project Init

## One-line summary
A runnable, empty FastAPI app — the skeleton every backend endpoint since has been added to.

## The problem
Before building auth, courses, chat, or exercises, there needs to be *a server that runs*. This milestone's only job: prove Python + FastAPI + Uvicorn can boot and answer one request.

## What we built
- `backend/pyproject.toml` — project metadata + tool config (later extended by M0.4 for Ruff/Black)
- `backend/app/__init__.py`, `backend/app/main.py` — the FastAPI app instance
- `backend/.env.example` — documents what environment variables the app needs (see M0.5)
- A `GET /health` endpoint returning `{"status": "ok"}`

## How it works
FastAPI is a Python web framework built on top of **ASGI** (Asynchronous Server Gateway Interface — the async successor to WSGI). FastAPI itself doesn't run the server; **Uvicorn** does — it's the actual process that listens on a port, accepts HTTP connections, and hands each request to the FastAPI `app` object to decide what to do with it.

```python
app = FastAPI(title=settings.app_name)

@app.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok"}
```

`uvicorn app.main:app --reload` means: "import the `app` object from `app/main.py`, serve it, and restart automatically whenever a source file changes" (`--reload` — invaluable for local dev, never used in production).

## Why FastAPI (and not Flask/Django)
- **Type hints become validation.** A route parameter typed `exercise_id: uuid.UUID` is automatically parsed and validated from the URL — an invalid UUID gets rejected with a 422 before the route body ever runs. Flask/Django require explicit parsing code for this.
- **Free OpenAPI docs.** Every route with typed request/response models automatically produces interactive docs at `/docs` (see M8.3) — no separate documentation effort.
- **Async-native.** FastAPI routes can be `async def` and I/O (like an LLM API call in M4.5) doesn't block the whole server while waiting.
- **Pydantic integration.** Request/response schemas (see every `schemas/*.py` file in this project) are just Pydantic models — the same validation library used for config (M0.5) and every API payload.

## Terms worth knowing
- **ASGI**: the interface between a Python web app and the server running it, supporting async. WSGI (Flask's/Django's original interface) is synchronous-only.
- **Uvicorn**: the ASGI server process. FastAPI is a framework; Uvicorn is what actually opens a socket and listens.
- **Health check endpoint**: a trivial endpoint (`/health`) whose only purpose is "is this process alive and responding?" — used by load balancers, container orchestrators (Kubernetes liveness probes), and uptime monitors.

## If asked in an interview

I picked FastAPI specifically for the type-hint-driven validation — a route can declare `exercise_id: uuid.UUID` and FastAPI handles parsing, validating, and rejecting bad input automatically, using the same Pydantic models I use for request/response schemas everywhere else in the app."
